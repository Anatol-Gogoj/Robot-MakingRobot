## 2. What changed since the previous handoff

### The encoder is index-referenced. That hypothesis is dead.

`HANDOFF.md` §2 named "the encoder was never index-referenced for position" as the leading
candidate, and said four issues would need re-planning if it were true. It is not true. **[bench]**

```
config.gpio10_mode                              = 0      (DIGITAL, not AUTO)
axis0.pos_vel_mapper.config.use_index_gpio      = 1
axis0.pos_vel_mapper.config.index_offset        = 0.0
axis0.pos_vel_mapper.config.index_offset_valid  = 1
inc_encoder0.config.cpr                         = 8192
```

The original grep that suggested otherwise was searching *this repo*. The settings were configured
on the hardware years ago and live in the ODrive's NVM. See `ODRIVE_CONFIG.md` (PR #74).

So **#45, #52, #54 and #55 keep their premises.** The Tier 3 ordering in the old handoff stands.

### But the reference is modulo ONE TURN, which nobody expected

The index search corrects the fractional position within a revolution and leaves the integer turn
count accumulating, because `pos_vel_mapper.config.circular` is `False`. **[bench]**

Two searches, several hand-turns apart:

| Search | `pos_estimate` after | Fractional part |
|---|---|---|
| first | `0.38` | **0.38** |
| second | `10.375702` | **0.3757** |

Agreeing within 1.8°, against a measured settle error of 0.86°.

**This is the single most important finding in this document.** It explains why
`index_offset_valid: True` and a `pos_estimate` that never returns to zero are not a contradiction,
and it is the whole of #55.

Evidence is two data points. A third would put it beyond doubt and costs one more index search.

### Three real faults, replacing the one that wasn't

**1. A floating thermistor input.** `ODriveError.THERMISTOR_DISCONNECTED` disarmed the axis
mid-procedure, giving `procedure_result = 3 (DISARMED)` on every index search. `clear_errors()` did
not clear it — the condition was live. The D5312s has no thermistor and never did; the input floated
and drifted across the disconnect threshold, which is why the fault was **intermittent**. **[bench]**

**This is the leading explanation for the original "the spin coater does not home properly"
report.** An intermittent fault that disarms the axis mid-search produces exactly that symptom.
**[inferred]** — plausible and well-supported, but not yet demonstrated by a long run of successful
homes. Disabled on the hardware 2026-08-13.

**2. `boot()` declared a datum from a search that never happened.** With the thermistor fault
active, `boot()` printed `datum established at the index mark` over an index search that had
disarmed. `InitialPos=-0.73` was the *pre-search* position, and `BootSettleErr` never printed at
all. **[bench]** Three silent failure paths, plus a fourth design bug — the settle targeted absolute
zero, which is only ever correct when the rotor happens to be near turn zero. Fixed in PR #72,
**never run**.

**3. The >1-turn guard compared absolute multi-turn positions.** It refused every post-spin home on
a healthy machine — `Position 10.38 is >1 turn from home datum 7.44` describes two positions 21°
apart. **[bench]** Fixed in PR #71, **never run**.

**Sending G-code over SSH** — `stty` cannot set 250000 baud (non-standard, needs `termios2`). Use
pyserial from PlatformIO's venv:

```bash
~/.platformio/penv/bin/python -c "
import serial,time
p=serial.Serial('/dev/rmr-mega',250000,timeout=0.3); time.sleep(3); p.reset_input_buffer()
p.write(b'M115\n')
for _ in range(60):
    l=p.readline()
    if l: print(l.decode(errors='replace').rstrip())
"
```

Opening the port resets the Mega via DTR. Harmless — nothing moves on boot — but it destroys the
in-RAM datum.

## 6. Do this next

All of it rotates the chuck. **A person must be in the room.**

**1. PR #72 case 2 — the highest-value single test.** The rotor is currently at `pos_estimate ≈
10.376`, many turns from zero, which is exactly the condition the old `t 0 0.0` settle target could
never handle. Reset the Mega (reconnecting the GUI does it via DTR), then:

```gcode
M752
```

Expect `BootSettleErr` to **print** — it never has — and the settle to complete in about a second
rather than crawling into the 8 s timeout.

**2. PR #71 — the post-spin home that used to be refused outright.**

```gcode
M751
M750 S1000 D10 A3 C3 H0
M752
```

Expect `DatumNormalised turns=<~160>`, then `HOME_SETTLE`, then `OK: INDEX_COMPLETE`.

**3. The `DEG` invariance check — do not skip this one.** Normalising the datum is only legitimate
because `fmod((pos − _homePos) × 360, 360)` is invariant under dropping whole turns. Confirm the
reported `DEG` is unchanged across a normalisation. **If `DEG` shifts, PR #71 is wrong even though
homing completes.**

**4. Third data point for the modulo-one-turn finding.** Index search, record the fractional part of
`pos_estimate`, hand-turn a couple of turns, index search again, compare. `M752` refusing on the
guard is fine — the search runs *before* the refusal, so the position still tells you what you need.

**5. Honest-failure check.** Disconnect the encoder index wire, reset the Mega, `M752`. `boot()` must
report *no valid datum* rather than announcing one, and the following `M752` must refuse rather than
settle to garbage.

Then merge, bottom-up, in the forced order, and resume Tasks 6–10.

## 7. Findings that must not be re-derived

- **The index reference is modulo one turn.** §2. Everything about datum comparison follows from it.
- **`pos_estimate` is a continuous multi-turn accumulator** (`circular: False`). It never returns to
  zero and is not supposed to.
- **The ODrive does not index-search on power-up** (`startup_encoder_index_search: False`), so the
  absolute frame is undefined after every ODrive power cycle until something crosses the index.
  `index_offset_valid: True` means "we know where the index is", not "we know where we are".
- **The ODrive config exists only in NVM.** `ODRIVE_CONFIG.md` records the load-bearing values, but
  it is not a backup. Run `odrivetool backup-config` before touching ODrive firmware.
- **`axis0.pos_estimate`**, not `axis0.pos_vel_mapper.pos_estimate`. The latter is `invalid property`.
- **`stty` cannot set 250000 baud.** Use pyserial.
- **The ODrive answers a bad property path with the literal string `invalid property`**, not silence.
  A wrong path and a dead link look different — deliberately.

## 8. Traps

- **A serial port has exactly one holder, and Linux will not enforce it.** Chrome, picocom, avrdude
  and odrivetool all want the same devices. Observed with Chrome *and* picocom holding
  `/dev/rmr-mega` simultaneously, each getting fragments. **Disconnect the UI before any upload.**
- **After flashing, the UI cannot reconnect** until PR #73 lands; reload the page. If the device
  does not reappear, unbind/rebind it:
  ```bash
  DEV=$(basename $(dirname $(grep -l 2341 /sys/bus/usb/devices/*/idVendor)))
  echo "$DEV" | sudo tee /sys/bus/usb/drivers/usb/unbind; sleep 2
  echo "$DEV" | sudo tee /sys/bus/usb/drivers/usb/bind
  ```
- **Both devices are CDC-ACM and swap numbers freely.** The ODrive has held `ttyACM0` — the Mega's
  old number. Always address them as `/dev/rmr-mega` and `/dev/rmr-odrive`; the udev rules are keyed
  on serial number for this reason (#65).
- **The ODrive USB link runs without its isolator** (#68). If `odrivetool` reports
  `LIBUSB_ERROR_IO` or dmesg shows `can't set config #1, error -71`, that adapter is back in the
  cable. The UART link is unaffected either way — `M753` and `M754` still work.
- **A cold ODrive emits garbage.** `M753` immediately after powering the rig returned 13 bytes of
  binary and 26 stale bytes. Wait and retry before concluding anything.
- **`ok` from Marlin does not mean the command succeeded.** Read the terminal marker.
- **Marlin compiles only sources listed in the feature's `build_src_filter`.** A new G-code file
  needs registering in `ini/features.ini` as well as declared and dispatched, or it fails at *link*
  time with `undefined reference`.

## 9. Decisions not to relitigate

The eight in `HANDOFF.md` §4 all still stand. Added since:

| # | Decision | Reason |
|---|---|---|
| 9 | **Normalise the datum into the current frame; do not merely relax the comparison.** | Comparing modulo one turn alone would leave `t 0 <_homePos>` commanding a move hundreds of turns long — the doomed crawl the original guard existed to prevent. PR #71 fixes comparison and target together. |
| 10 | **No write passthrough to the ODrive from G-code.** | `M754` is read-only by construction. A general passthrough would put `w axis0.requested_state 8` one text box away from spinning the chuck, on a machine whose mechanical E-stop is still #20. |
| 11 | **The touch UI auto-reconnects; the controller UI does not.** | The controller is open during uploads, and an automatic re-attach would race avrdude for the port. Recorded in the file so the asymmetry is not "fixed" later. |
| 12 | **Remote desktop shares the existing session; never per-user sessions.** | One serial port, one holder. Two desktops means two browsers means a fight over `/dev/rmr-mega`. |

## 11. Working agreements

From the original handoff, still in force: one issue → one branch → one PR; correctness over
efficiency; every firmware change builds before push; adversarial review before commit; every PR
body carries bench steps.

**Note that PRs #70–#74 did NOT get an adversarial multi-lens review.** Each says so in its own body.
They are small, mostly read-only, and #70 has run on hardware — but that is not the same thing, and
the process exists because three of the four original fix PRs had a self-inflicted regression caught
by exactly that review.

Added:

- **No motion commands without a person in the room.** `G28`, `G1`, `M280`, `M750`, `M752` and any
  G-code program. The machine has a 5000 RPM chuck, a UV lamp and a solenoid, and **no mechanical
  E-stop** (#20).
- **Say what you are about to run before running it**, for anything that touches the machine.
- **Find the log before changing anything.** Nearly every failure in this project has been silent or
  actively misleading — a hang instead of an error, a green success on a red failure, packets leaving
  with nothing coming back. Each was settled by one line of log after an hour of guessing.
