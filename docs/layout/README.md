## 3. Decisions, one recommendation each

1. **The UI pages move to `ui/`, with their tests.** `tests/` checks only these two pages (`tests/README.md:3`), so the two belong together.
   - Cost: `tests/run.mjs:17` sets `root = join(here, '..')`. That becomes the page folder, which is a simpler rule.
   - Cost: `tools/sync_runlog.py:27-28` and `tools/contrast_check.py:21` get the new path.
   - Cost: the Pi's kiosk URL becomes `/ui/RMR_Touch.html` (`pi-panel/README.md`, 11 lines). The Pi is not in service, so nothing live breaks there.
2. **Firmware goes under `firmware/`, and its folder name stays `Marlin-2.1.2.7`.**
   - Renaming it to lower case on Windows takes a two-step `git mv`, and the version in the name is useful.
   - One level deeper adds 9 characters to every build path, against the AVR toolchain's 260-character limit.
     - The longest tracked path under `Marlin-2.1.2.7/` is 128 characters (an `ftdi_eve_touch_ui` font file).
     - This worktree's base path is 83, so today's longest is 211 and the move makes it 220.
     - PlatformIO's `.pio/build/...` object paths run longer than the sources. The build in section 5 step 3 is the real check.
   - G-code programs sit next to it in `firmware/programs/`, since they are what the Mega runs.
3. **`tools/` stays flat.** The generators load each other as siblings:
   - An external head-CAD build execs `tools/build_filter_cartridge.py` by path.
   - `build_box_model.py` reads `draw_wiring.py`.
   - `build_mask_stowage.py` uses `draw_wiring` panel sizes.
   Splitting them into `cad/` and `wiring/` would mean a Python package and changing every import for nothing an operator sees. Only their output paths change.
4. **CAD folders take the form `<group>_<name>`, with the group the ID prefix of every file inside.** `6-01_...` lives in `6_filter_cartridge/`.
   - Unpadded, as in the partner head-CAD repo that shares the ID space, so a listing sorts `10_`...`15_` before `6_`. That is acceptable, because the ID, not the sort order, is what people look for.
   - No spaces anywhere, so no path needs quotes.
5. **Docs split by use:**
   - `hardware/`: what the machine is (pins, ODrive config, J11 pinout).
   - `process/`: how a layer is made (dispense retune, Run Log design).
   - `bench/`: what was run and measured (`RUN_SHEET.md` with its dated results).
   - `adr/`, `wiring/` and `spincoater/` stay where they are.
6. **Retired code goes under `archive/`.** `SpincoaterStage/` and `SpincoaterStage.ino` join `e-axis-programs/` as `archive/spincoater-nano/`. `claude.md` already calls them "retired reference", and the root stops looking like it has two firmwares.
7. **`claude.md`, `README.md` and `AI_ATTRIBUTION.md` stay at the root.** `CLAUDE.local.md` and the tools that read `claude.md` expect it there.

## 5. Order: one issue, one branch, one PR each

Each PR is `git mv` plus reference fixes, with no content changes. Each ends with the old path found zero times outside dated records (RUN_SHEET results, merged ADR text) and the test suite at its current baseline with no failures.

1. **docs and archive.** No code touches these paths, so it is the cheapest PR and proves the reference check.
2. **ui/ and its tests.** Run `node ui/tests/run.mjs`. Change the bench laptop's login item the same day the clone pulls it.
3. **firmware/.** `pio run -e mega2560` from the new folder; the avrdude verify is not needed for a move.
4. **CAD**, one PR per group (6-8, 10, 11, 12-13, 14, 15, 90), each with that group's renames from `CAD_NAMING.md`. Rerun the group's generators and diff the geometry, not only the names. Gripper-A waits for its SolidWorks pass.

Open PRs and other branches that touch a moved path need a rebase after each step. `git log --follow` keeps every file's history.
