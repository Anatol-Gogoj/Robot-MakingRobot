# ADR-0002: An existing spin-coater datum is never moved silently
Status: Accepted; Date: 2026-08-11, frame rule added 2026-08-14 (handoff decisions 3, 4 and 9); Scope: `spincoater.cpp` datum, `doIndexHome()`, `doSetHome()`, M750 `H1`
Context: The machine builds multilayer DEAs, so the spin-coater datum carries layer-to-layer angular registration. The original firmware "self-healed" after a failed home by re-datuming wherever the rotor stopped (a blanket `doSetHome()` fallback). That self-healing was bug #41: it silently destroyed the operator's zero on the most common failure path. On 2026-08-13 the bench showed that the index search corrects only the fractional turn and leaves the turn count accumulating (`circular: False`), so the datum and the rotor can be hundreds of turns apart in absolute terms and a fraction of a turn apart in the sense that matters.
Decision: Three rules. (1) A failed index home never overwrites an existing datum. A first datum is adopted after a failed home only by `M750 H1`'s fallback `doSetHome()`, and only when none exists; `doIndexHome()` refuses to settle without a valid datum. (2) A datum is never captured from a moving axis: `doSetHome()` and the settle fallback refuse above 0.05 turns/s (about 3 RPM), and every datum-writing read goes through `feedbackStable()` (two consistent reads), never a single `feedback()`. (3) Before the return-to-datum move, the datum is normalised into the current frame by dropping whole turns (`_homePos -= roundf(_homePos - pos)` in `doIndexHome()`). That keeps the angle exactly (what `DEG` reports is invariant) and makes the settle a sub-turn move.
Rejected: Restoring automatic re-datuming after a guard failure: that self-healing was bug #41
Rejected: Relaxing only the datum comparison to modulo one turn: `t 0 <_homePos>` would still command a move hundreds of turns long at 0.25 turns/s, the crawl the original guard existed to prevent
Consequences: Easier: a failure is reported, and the operator's zero survives it. Harder: after any Mega reset the datum is gone (RAM only, #54) and `M751` must be run again before a registration-critical layer.
Revisit if: the datum is persisted (#54) or the encoder becomes absolute.
