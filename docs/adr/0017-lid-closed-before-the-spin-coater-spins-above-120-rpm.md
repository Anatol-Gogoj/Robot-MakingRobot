# ADR-0017: The lid is closed before the spin coater spins above 120 RPM, and homing and index searches may run with it open
Status: Accepted (owner rule, 2026-10-21, issue #191); Date: 2026-10-21; Scope: `RMR_Controller.html` and `RMR_Touch.html`: `runSpinBlock()`, `spinStart()`, the Syringe block's dispense, purge and Lower paths, and the lid tracking (`lidTrackTx()`, `lidState()`); the firmware gate is issue #192
Context: The browser UIs sent `M750` from the Spin Coater block and the spin panel's Start Spin with the lid wherever the last command left it, normally open after the Syringe block. On 2026-10-21 the owner set the rule: homing with the lid open is fine, because it lets the operator see whether the chuck is aligned, and `M752` and the boot index search may run with the lid open, but the lid must be closed before the spin coater spins above about 120 RPM. The lid is the servo on `M280 P1`; 115 deg closes it over the chuck and 30 deg opens it (`claude.md`, Servos). Nothing reads its position: the pin-39 switch of the disabled `UV_LID_INTERLOCK` is not wired (gotcha 15), so the UIs know only the angle last commanded.
Decision: Above `SPIN_LID_RPM` (120), the Spin Coater block and Start Spin send `M400`, then `M280 P1 S<closed> T<ms>`, before the `M750`, with the closed angle and ramp time the UV block uses (its `uvLidClose` field, `rmr.lidMoveMs`, 800 ms by default). An `M750` with no number after `S` counts as the firmware default, 5000 RPM. The block waits for the lid move's `ok`, and Start Spin sends the `M750` only on that `ok`; Marlin sends it after the `T` ramp has finished (`M280.cpp`). The block reopens the lid it closed, to the UV block's open angle, only after its own `M750` printed `OK: CYCLE_COMPLETE` or `ERR: CYCLE_COMPLETE_NO_HOME`: `M750.cpp` prints either one only after its ramp-down loop has read `|RPM| <= 6` and settled for 1 s, and as its last line. What `H1` turns after the ramp-down is an index search and its settle, which the rule allows with the lid open, so a chuck still coasting from a failed search after `ERR: CYCLE_COMPLETE_NO_HOME` does not keep the lid closed. Every other ending leaves the lid closed and says why: a Stop, a fault, a timeout, no marker, an earlier command's marker only, and every early return of `M750` (`RAMP_TIMEOUT`, `RAMP_STALL`, `MEASURE_LINK_LOST`, `Samples=0`, `DECEL_LINK_LOST`, `DECEL_STALL`, the `M410` abort, a failed boot or closed loop). On those endings with the lid closed the block fails, which ends a Run All there, so the UV block cannot reopen the lid after its cure. Start Spin never reopens the lid. Each page records the last lid angle commanded on the port from any path: its own writes on Web Serial, the bridge's TX echo of every client and button otherwise. `M280 P1 S<n>` with n >= 0 sets it, and every `G28` sets 30 deg, partial or bare, because `G28.cpp` moves the lid to 30 deg before any axis; only `G28 O` changes nothing, since it may return before that. The lid counts as closed above the larger of the UV block's open angle and 30 deg, and always at the closed angle or past it. While it was last commanded closed, the Syringe block's dispense, purge (Run All's purge-on-run included) and Lower helper refuse with nothing sent, saying to open the lid with the Lid button once the chuck has stopped. Prime does not lower B and is not refused, and nothing in the Syringe block moves the lid. A connect, a disconnect and the firmware's `start` make the state unknown, and an unknown state does not block.
Rejected: Treating `STATE:STOPPED` as proof: on the `M410` abort path `M750.cpp` prints it right after `setVelocity(0)` and returns, with the chuck still turning at speed
Rejected: Reopening on the `M750`'s bare `ok`: `ok` says the line was parsed, not that the chuck stopped (gotcha 25)
Rejected: Blocking the syringe on an unknown lid state: after every connect and reset the operator would have to send a lid command before the first dispense; the owner chose that unknown does not block (issue #191)
Rejected: Moving the lid from the Syringe block: the block would then open a lid over a chuck it has no proof is stopped
Consequences: Easier: a spin above 120 RPM can no longer start from these two paths with the lid where the Syringe block left it, and a dose cannot be lowered into a lid one of them closed. Harder: a Spin Coater block above 120 RPM whose `M750` ends without one of the two markers now fails the run where it used to pass on the `ok`; at or below 120 RPM nothing changed. The guard is only as good as the commanded angle: a lid moved by hand, or still closed after a reset (`servo_init()` attaches and detaches the servo at boot without moving it), is not seen, so an unknown state can lower the syringe into a closed lid. The bridge echoes a write before it makes it, so a lid command whose write then failed (the UIs log it as a bridge error) still counts, until the next lid command, `G28` or `start`. An `M750` typed in the console or run by the Program Runner, and the Manual-tab B jog, are not covered; the firmware gate (#192) is the layer for those. Open bench question: the speed at which the ODrive turns the rotor during `ENCODER_INDEX_SEARCH` is set in the ODrive's own configuration and is not recorded in `ODRIVE_CONFIG.md`. If it can exceed 120 RPM, the index searches that run with the lid open (`M752`, and the boot search of the first `M751` or `M752` after a reset) break the rule, and so does the chuck coasting from a failed `H1` search when the block reopens after `ERR: CYCLE_COMPLETE_NO_HOME`. The settle after the search is capped at 0.25 rev/s, which is 15 RPM (`spincoater.cpp`, `trap_traj.config.vel_limit`).
Revisit if: the firmware gate (#192) lands, a lid-closed switch is wired so the UIs can read the lid instead of tracking commands, or the index search speed is measured above 120 RPM.
