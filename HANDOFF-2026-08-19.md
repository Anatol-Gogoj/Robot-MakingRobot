## 2. What the 2026-08-17 bench session established

### PR #72 — boot() settles to the nearest index mark. Confirmed.

`BootSettleErr` **printed for the first time in this machine's history.** Under the old code it never
printed, because the settle never converged.

The run that matters was taken with the rotor at `InitialPos=3433.00` turns. **[bench]**

| | Old code (`t 0 0.0`) | New code (`roundf(p0)`) |
|---|---|---|
| Settle target | 0.0 | 3433 |
| Distance to travel | 3433 turns | ~0.4 turns |
| Time at `vel_limit` 0.25 turns/s | **3.8 hours** | 1.6 s |
| Outcome | killed by the 8 s watchdog | `BootSettleErr=0.00 deg` at 2.2 s |

**An earlier run the same day also passed but proved nothing**, because an ODrive power cycle had
zeroed `pos_estimate` — with the rotor near zero, `roundf(p0)` is 0, which is exactly what the old
code did. Only the 3433-turn run discriminates. If this is ever re-tested, **reset the Mega, not the
ODrive**: `pos_estimate` lives in the ODrive, and a DTR reset of the Mega leaves it intact.

### PR #71 — datum normalisation. Confirmed, including the invariance it rests on.

First successful post-spin home this machine has produced: `DatumNormalised turns=-206
newHomePos=198.00`, then `HomeSettleErr=0.88 deg`, `OK: INDEX_COMPLETE`. The old guard would have
refused this exact case with *Position 198 is >1 turn from home datum -8.00*. **[bench]**

**The DEG-invariance gate passed.** This was the one test that could have invalidated a fix that
otherwise appears to work:

| Moment | `POS` | `DEG` |
|---|---|---|
| `M751` — datum set | 107.00 | **0.00** |
| after spin, `M752` normalises `turns=-104` to `newHomePos=211.00` | 211.00 | **359.95** |

The datum moved by **exactly 104 whole turns** and the reported angle for the same physical position
came back **0.05° from zero**, against a 2° threshold. Dropping whole turns does not move the
angular frame. **[bench]**

**The physical-mark corroboration was lost.** Someone powered the ODrive down overnight; the rotor
drifted ~30° while unpowered and free. The numeric result stands on its own, but the mark check is
cheap and worth redoing — see §6.

**Redone and passed on 2026-08-19** — the mark returned. See §6.

### New bug: the measure phase aborted on a healthy link, every time

`measureSpeed()` armed `lastTelemOkTime` once on entry (`M750.cpp:83`) and never refreshed it. The
loop does its own `feedback()` calls and never reaches `spinTelemetry()`, the only other place that
refreshes it. The 3-second dead-link watchdog therefore fired **exactly 3000 ms into MEASURING,
regardless of link health.** **[source]** + **[bench]**

Observed four times: twice at `D10`/1000 RPM, once at `D30`/5000 RPM, and once during the T3 run
where the abort timestamped at 6.31 s against `MEASURING` at 3.30 s — 3.01 s. The link was provably
fine: `RAMP_UP` completed each time, and its exit condition needs live telemetry; `M752` then ran
clean over the same UART seconds later.

This is a regression introduced alongside the watchdog itself (issue #42, PR #57). Fixed in PR #76.

### `M750`'s `D` parameter excludes the ramps

`D` is the **hold/measure duration only** — `M750.cpp:11`. **[source]** The 14 August handoff
predicted `turns=~160` for `M750 S1000 D10 A3 C3` assuming `D` covered the whole cycle. It does not;
a complete cycle is ~217 turns.

Corroborated at the bench: a run truncated by the 3 s abort banked **104 turns** against a predicted
100 — 25 ramping up, 50 during the 3 s measure, 25 ramping down. **[bench]**

### The settle error you see is the tolerance, not the machine

Eight settle errors were recorded across the session: 0.09, 0.19, 0.29, 0.37, 0.88, 0.93, 0.95 and
1.00 degrees. All under 1.08°, and that is not a coincidence — the convergence test is
`fabs(pos - _homePos) < 0.003f` turns, which **is** 1.08°. The settle exits the moment it drops under
the ceiling, so where it lands is luck. **[source]**

Encoder resolution is 360/8192 = 0.0439°, about 25× finer. If tighter homing is ever wanted, that one
constant is the knob; the costs are longer settles and the risk of never converging against static
friction.

### The accumulator has a hard ceiling at ~32 768 turns

`pos_estimate` never wraps, and everything downstream is a 32-bit float whose step size grows with
magnitude. This stopped being theoretical at 3433 turns. **[source]**

| `pos_estimate` | Float step | In degrees | Consequence |
|---|---|---|---|
| 3 433 | 0.000244 t | 0.088° | reached; settle errors quantised to this |
| 16 384 | 0.00195 t | 0.70° | inside the 0.003-turn tolerance, barely |
| **32 768** | 0.0039 t | 1.41° | **step exceeds the tolerance** |

Above ~32 768 turns the difference between two nearby positions is either exactly zero or larger than
the tolerance — nothing in between — so the settle can only pass on a bit-identical match and will
otherwise time out on a mechanically perfect machine. At ~833 turns per `fullcode.gcode` run that is
roughly **39 production runs per ODrive power cycle**. The mitigation is free: power the ODrive down
periodically, which zeroes the accumulator.

The observed `BootSettleErr=0.00` and `HomeSettleErr=0.09` at 3433 turns are *exactly zero and one
float step*. Do not read 0.00° as perfection.

### Two UI defects, both of which blocked diagnosis

**No identity check on connect.** Both USB devices are CDC-ACM and swap `/dev/ttyACM` numbers freely.
On 2026-08-17 a power cycle exchanged them — the ODrive vacated `ttyACM0` at 16:03:58, the Mega
re-enumerated first at 16:04:07 and claimed it — and Chrome's remembered port then pointed at the
ODrive. Every G-code came back `unknown command`, which is the **ODrive's ASCII protocol answering**,
not Marlin refusing. It reads exactly like the firmware losing its command set, and it cost most of a
session. **[bench]**

**The Verbose checkbox could never show telemetry.** `processLine()` let `TELEM:` lines fall through
when Verbose was ticked, then excluded them from `logRx()` unconditionally a few lines later. No
setting anywhere in the UI would print a `DEG=` value; the circular dial was the only angle readout
and it cannot be read to 2°. This forced the entire T3 measurement onto SSH. **[source]**

Both fixed in PR #78, stacked on #73.

unifying, but **not demonstrated**: at least one GUI failure fell in a window with no logged USB
event.

**Swap the cable and move it to a different port before anything else.** It tests both problems at
once and costs nothing.

**Never address either device by `ttyACM` number.** They swap. Always `/dev/rmr-mega` and
`/dev/rmr-odrive`; the udev rules are keyed on serial number for exactly this reason (#65). In
Chrome's port picker, select by USB id.

**Sending G-code over SSH** — `stty` cannot set 250000 baud. Use pyserial:

```bash
~/.platformio/penv/bin/python -c "
import serial,time
p=serial.Serial('/dev/rmr-mega',250000,timeout=0.3); time.sleep(3); p.reset_input_buffer()
p.write(b'M115\n')
for _ in range(60):
    l=p.readline()
    if l: print(l.decode(errors='replace').rstrip())
"
```

Opening the port resets the Mega via DTR. Nothing moves on boot — `Spincoater::boot()` is deferred to
the first `M750`/`M751`/`M752` — but it destroys the in-RAM datum. **[source]**

**Relaunching the UI over SSH** needs `--ozone-platform=wayland`, or Chrome picks the X11 backend and
dies on the missing X cookie. It also needs the session bus:

```bash
export XDG_RUNTIME_DIR=/run/user/1000
export DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/1000/bus
```

A plain backgrounded launch is reaped when the SSH session ends. Use `systemd-run --user`.

## 7. Findings that must not be re-derived

- **The index reference is modulo one turn.** Everything about datum comparison follows from it.
- **`pos_estimate` is a continuous multi-turn accumulator** (`circular: False`). It never returns to
  zero and is not supposed to. It has a **float ceiling at ~32 768 turns** — §2.
- **`boot()` re-datums to wherever the rotor is.** So `M752` immediately after a Mega reset can never
  exercise datum normalisation; `roundf(_homePos - guard_pos)` is always 0. Set the datum first,
  accumulate turns, and do not reset in between.
- **A Mega DTR reset does not touch `pos_estimate`.** That lives in the ODrive. To preserve turn
  count, reset the Mega; to zero it, power the ODrive.
- **`M750`'s `D` is the hold duration, exclusive of ramps.**
- **`M750 S<rpm>` holds `rpm + 10`, not `rpm`.** `M750.cpp` commands a deliberate +10 RPM overshoot
  so the ramp-up threshold (98 % of target) is reachable, and never backs it off — the measure phase
  runs at the overshot speed for its whole duration. The first statistics block this machine produced
  reads `MeanRPM=1009.88` against `S1000`, which is 0.12 RPM from the *commanded* 1010 and 9.88 from
  the *requested* 1000. Do not read that 9.88 as a tracking error; the loop is tracking almost
  perfectly. It is 1 % fast at `S1000` and 0.2 % fast at `S5000`. **[bench]** + **[source]**
- **The settle tolerance is 1.08°** (`0.003f` turns). Reported settle errors are bounded by it, not
  by the machine.
- **The ODrive does not index-search on power-up** (`startup_encoder_index_search: False`).
  `index_offset_valid: True` means "we know where the index is", not "we know where we are".
- **The ODrive config exists only in NVM.** `ODRIVE_CONFIG.md` (PR #74) records it but is not a
  backup. Run `odrivetool backup-config` before touching ODrive firmware.
- **`axis0.pos_estimate`**, not `axis0.pos_vel_mapper.pos_estimate`.
- **`stty` cannot set 250000 baud.** Use pyserial.
- **The ODrive answers a bad property path with `invalid property`**, and an unrecognised command
  with `unknown command`. Neither looks like Marlin, which says `echo:Unknown command: "M750"`
  followed by `ok`.

## 8. Traps

- **A serial port has exactly one holder, and Linux will not enforce it.** Two readers each get
  fragments. Disconnect the UI before any SSH session that opens a port, and vice versa.
- **The two devices swap `ttyACM` numbers on re-enumeration.** Observed mid-session.
- **`ok` from Marlin does not mean the command succeeded.** Read the terminal marker.
- **Reaching `IDLE` proves nothing** about an index search — `procedure_result` is the only
  discriminator. This is the #43 trap.
- **A cold ODrive emits garbage.** Wait 30 s and retry before concluding anything.
- **Marlin compiles only sources listed in the feature's `build_src_filter`.** A new G-code file needs
  registering in `ini/features.ini` as well as declared and dispatched, or it fails at *link* time.
- **`M115` and the boot banner report the *previous* build's timestamp after an incremental build.**
  `__DATE__` and `__TIME__` are baked into whichever translation unit contains them — `M115.cpp:64`
  and `MarlinCore.cpp:1292`. PlatformIO recompiles only what changed, so a build that touches one
  G-code file links a new image while both strings go on naming the old build. On 2026-08-19 a
  correctly flashed board reported `Aug 13 2026 19:45:48` and read exactly like a failed upload.
  **avrdude's post-write verify is the honest check** — it reads the image back off the chip and
  compares it against the hex. Only a clean rebuild refreshes the strings. **[bench]**
- **`pkill -f chrome` matches the shell running it** when that command line contains the word. Use
  `pkill -x chrome`.
- **`M999` does not restart the board after `M112` on this machine.** A **GUI disconnect/reconnect is
  enough** — it toggles DTR, which resets the Mega. A physical USB replug was *not* needed on
  2026-08-19, contrary to what this trap said before. Either way the in-RAM datum is erased; send
  `M751` again. **[bench]**
- **The bench laptop's clock jumped ~3 days during the 2026-08-17 session** when NTP corrected it. Any
  log timestamp written before the correction is offset. It is NTP-synced and correct now.
- **Never pipe a long bench run through `head`.** It closes the pipe, kills the SSH session, and can
  cut a script off mid-sequence. Redirect to a file on the laptop and fetch it afterwards. This
  happened on 2026-08-17 and cost a full T3 run.

## 11. Working agreements

From the original handoff, still in force: one issue → one branch → one PR; correctness over
efficiency; every firmware change builds before push; adversarial review before commit; every PR body
carries bench steps.

**PRs #70 to #78 have NOT had an adversarial multi-lens review.** Each says so in its own body. #76
and #78 have reproduced bench symptoms behind them, and #78's telemetry fix was verified
behaviourally in a browser — but that is not the same thing, and the process exists because three of
the four original fix PRs had a self-inflicted regression caught by exactly that review. **PR #76 is
itself a regression in PR #57**, which is an argument for the process, not against it.

Also in force:

- **No motion commands without a person in the room.** `G28`, `G1`, `M280`, `M750`, `M752` and any
  G-code program. 5000 RPM chuck, UV lamp, solenoid, and **no mechanical E-stop** (#20).
- **Ask explicitly whether a person is at the machine.** Do not infer it from context. This was got
  wrong on 2026-08-17: two runs turned the chuck after the on-site colleague had left.
- **Say what you are about to run before running it.**
- **Find the log before changing anything.** Nearly every failure in this project has been silent or
  actively misleading. Each was settled by one line of log after an hour of guessing — and on
  2026-08-17 three separate theories died to one `journalctl` query each.
